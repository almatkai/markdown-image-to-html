# Native V2 — Markdown Image to HTML

Rust implementation of the single **Markdown Image to HTML** no-view command. It replaces `raycast.markdown-image-to-html` with `com.tezbar.native.markdown-image-to-html`. The command takes optional `markdownImage` and `imageWidth` text arguments, with the original command-scoped required image-width preference (default `"300"`). It chooses a matching argument, selected text, then clipboard text; transforms every matched image while preserving surrounding text; and pastes the resulting text once.

Original Raycast author: **qeude**; contributor: **daniellacoste**. Own V1 source: `almatkai/markdown-image-to-html` at `54ce6a02c3e7f4aa75d1b3efa6af08d667673d55`. Raycast reference: `raycast/extensions` at `6734d85992290066fd31a7f5bee3cca3d3545a1a`, `extensions/markdown-image-to-html`. Source and asset notices are retained in [NOTICE.md](NOTICE.md) and `licenses/`.

The intentional V1 bug fix accepts manifest argument `markdownImage`. The source accidentally reads `mardownImage`; V2 accepts that legacy typo only when the canonical key is absent. An empty or nonmatching canonical string still wins over the typo and then falls back to selection/clipboard. Non-string argument values (including JSON null) are malformed launcher data and fail before any OS request. Unknown unrelated argument keys are ignored.

Width follows actual launcher **strings**, not the inaccurate TypeScript numeric annotation. A nonempty argument accepted by JavaScript `Number` coercion retains its exact spelling, including whitespace, zero, negative values, exponent/hex/octal/binary notation, or Infinity. Otherwise the preference is used without numeric validation; only missing/null preference becomes `300`. JSON-representable preference values retain JavaScript template-string conversion, including booleans, arrays, objects, and numeric formatting. Objects whose own non-callable `toString` shadows the default fail conversion, matching JavaScript.

Matching follows `/!\[(.*?)]\((\S+)\)/g`: lazy alt, greedy URL, no balancing of parentheses, all matches, and surrounding text retained. Dot excludes LF, CR, U+2028, U+2029; URL whitespace uses the exact JavaScript set (U+0085 is **not** whitespace). Transport strings must be valid UTF-8. For this pattern, UTF-16 JavaScript matching and UTF-8 Rust matching agree on representable scalar strings: delimiters and excluded whitespace/line terminators are BMP characters, and no capture boundary splits a surrogate pair. Lone surrogates are outside the transport contract.

Output is exactly `<img width="..." alt="$1" src="$2"/>` with **JavaScript replacement-string** substitution across the entire template, including dollar patterns supplied by a preference (`$$`, `$&`, `$1`, `$2`, `$01`, `$02`, prefix and suffix tokens). Captures are inserted once, without recursive substitution. No HTML escaping, sanitization, rendering, or evaluation occurs. The command constructs and pastes text.

The production adapter uses `payload.argumentValues` and the already resolved `payload.preferences`. It never interprets preference definitions as saved values. Its only routes are `core:platform:selected-text []`, `clipboard:read []`, and `core:platform:paste-text [text]`. A valid argument performs no reads. Selection transport failures or malformed non-string responses mean unavailable selection; clipboard transport failures or malformed responses are errors. Empty clipboard strings mean no match. Oversized strings are explicit limit errors. The no-match message remains:

> No valid markdown image found as parameter, selected or in your clipboard.

A paste acknowledgement must be an object with `ok: true`, no non-null `error`, and `success` absent or true. Any transport failure or malformed/negative acknowledgement reports a native error and is never retried. A manual relaunch can repeat an effect that occurred before its acknowledgement was lost. No extra copy/hide RPC is issued; the beta paste operation performs clipboard, hide, focus, and paste itself. No source selection log or actual user text is logged or included in errors.

The adapter validates command and operation before effects. It accepts launch and harmless dispose/refresh lifecycle calls; unknown commands/actions/search/load-more operations fail. It needs no UI, browser, network, persistent storage, or additional permissions. Success is a native `no-view` result; errors are native `Err` results. The pinned beta has a no-view notification gap, so a visible toast/HUD is not promised and no unsupported public notification RPC is invented.

Resource limits are checked before paste: 4 MiB per source string and chosen width, 16 MiB output, and a 64 MiB conservative replacement-work budget. Work starts at source UTF-8 byte length and charges source length plus full replacement-template length for each match. Checked arithmetic prevents overflow. This bounds repeated suffix searches and preference prefix/suffix substitution expansion, including repeated empty-capture substitutions. A large many-image input may reach the work limit before the byte limits. These are resource limits; width has no positivity/integer restriction. Oversized launch strings fail before reads; oversized selection/clipboard and conversion failures never paste.

See [INTEGRATION.md](INTEGRATION.md) for stable compiled-in integration and [VALIDATION.md](VALIDATION.md) for checks. Real macOS and Windows selected-text, clipboard, focus restoration, and paste QA remain **not-run**. Cross-compilation and mocked routes do not establish real platform behavior.
